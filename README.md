# 博弈32张

将线下「32张」棋牌玩法搬到线上的独立产品，面向棋牌爱好者及亲友互动场景，支持单机人机对战与多人实时对战。

本项目由作者独立完成功能设计、页面交互、前后端开发及部署验证；玩法参考线下规则，交互参考棋牌小程序。人机对手与自动托管采用规则及概率策略，**未接入大模型，也不需要模型 API Key**。游戏使用虚拟积分，不包含真实货币交易。

## 快速体验

安装并启动后，浏览器访问：

- 单机人机对战：<http://localhost:3000/>
- 多人大厅：<http://localhost:3000/online.html>
- 游戏规则：<http://localhost:3000/?tab=rules>
- 496 种两牌组合：<http://localhost:3000/?tab=table>

多人体验需要至少两个独立的浏览器会话，例如普通窗口与无痕窗口，或两台设备。房主创建房间并分享四位房间码，其他玩家输入房间码加入，再由房主开始。相同浏览器的同源页面会共享玩家身份，因此不要仅用两个普通标签页模拟两名玩家。

项目曾完成 Railway 部署验证。本仓库不承诺有持续可用的公网服务，运行方法见下文。

## 产品场景与功能

产品将线下聚会中的棋牌互动延伸到线上，使参与者可以通过浏览器加入同一房间，也可以在没有其他玩家时使用人机模式。

| 功能 | 当前实现 |
| --- | --- |
| 单机人机对战 | 支持配置人数、局数或时长，与规则策略对手进行对战；支持本地存档恢复 |
| 多人实时对战 | 房间码创建与加入，2～8 人对局；经典四人模式要求 4 人 |
| 牌局设置 | 联机房支持 5、10、20、30 局，或 10、20、30 分钟，由房主创建时确定 |
| 对战操作 | 发牌、看牌与搓牌、蒙吃选择、按规则行动、比牌及虚拟积分结算 |
| 规则说明 | 页面内提供规则、特殊牌型和 496 种两牌组合查询 |
| 异常处理 | 操作超时托管、断线身份恢复、断线超时处理与房主转移 |

这里的房间机制是**通过房间码邀请加入**，尚未实现随机匹配队列。

## 关键设计与取舍

### 将线下规则转换为明确的操作流程

线下对局可以由参与者口头解释和判断，线上则需要明确每个阶段能做什么、轮到谁、操作是否合法，以及何时结束一局。项目将蒙吃选择、搓牌、行动、比牌与整场结束拆成状态，并在界面显示当前回合、可用操作和事件记录。

单机版与联机服务端共用牌型判定引擎，减少两端牌型解释不一致的问题。联机版由服务端处理发牌、操作资格和结算；客户端按玩家身份接收状态，未公开的对手手牌不会直接展示给其他玩家。

### 区分操作超时与网络断线

两类等待采用不同规则：

| 情况 | 当前处理方式 |
| --- | --- |
| 玩家保持连接，但没有操作 | 每次等待 30 秒，前两次超时继续等待，第 3 次超时后进入自动托管；联机托管随后按策略执行行动 |
| 玩家网络断开 | 保留座位 60 秒等待重连；对局中超时未恢复则托管，等待房间或已结束状态下则移除玩家 |
| 房主断线超时 | 将房主身份转移给其他仍在线玩家 |

这些机制用于减少单个玩家暂离或断线对整桌流程的影响。具体时限是当前设计配置，尚未通过用户研究证明最优。

### 用策略对手支持独立体验

人机对战让用户不必先凑齐真人玩家即可体验玩法。对手根据牌力、合法操作、对局阶段等条件作出决策，并加入一定随机性。它不是大模型智能体，也不代表最优博弈策略。

### 保持原型运行方式简单

前端使用原生 HTML、CSS 与 JavaScript，Node.js 服务同时提供静态页面及 Socket.IO 联机接口，降低本地启动与单实例部署的复杂度。房间状态暂存于服务端内存，因此当前实现优先用于个人作品演示和小规模试用。

## 本地运行

推荐使用 Node.js 22 或更新的受支持 LTS 版本，以及随附的 npm。

在项目根目录执行：

```bash
npm ci
npm start
```

默认端口为 `3000`。开发时可使用自动重启：

```bash
npm run dev
```

更换端口，例如在 PowerShell 中：

```powershell
$env:PORT = '3001'
npm start
```

在 macOS / Linux 中：

```bash
PORT=3001 npm start
```

同一局域网中的其他设备可通过 `http://主机局域网IP:3000/online.html` 加入，需允许相应网络端口访问。联机模式必须运行 Node.js 服务，不能仅双击 HTML 文件启动。

## 测试与验证

运行现有集成测试：

```bash
npm test
```

当前测试会自动在本机 `32123` 端口启动临时服务，使用两个 Socket.IO 客户端检查房间设置、断线后的玩家身份恢复及五局对战结束流程，也包含部分规则断言。测试端口需保持空闲。

牌型引擎还提供独立的完整组合校验，可在项目根目录执行：

```bash
node -e "const fs=require('node:fs'),vm=require('node:vm');const c={window:{}};for(const p of ['js/data.js','js/engine.js'])vm.runInNewContext(fs.readFileSync(p,'utf8'),c);const r=c.window.ENGINE.verify();console.log(JSON.stringify(r,null,2));process.exitCode=r.ok?0:1;"
```

该校验按内置牌型表比对 496 种两牌组合，并检查两张牌交换顺序后的判定。它验证规则实现与表的一致性，不等同于对线下规则本身的独立认证。

现有自动化测试不代表所有页面交互、30 秒超时、60 秒断线、设备兼容性或高并发性能均已完整覆盖。

## 部署说明与已知限制

部署平台需要支持持续运行的 Node.js 进程及 WebSocket / Socket.IO。安装命令为 `npm ci`，启动命令为 `npm start`，端口读取平台提供的 `PORT`，默认 `3000`。前后端同源部署，无需配置额外模型密钥。

- **房间不持久化：** 服务重启、休眠或重新部署后，内存中的房间与进行中的对局会丢失。
- **默认单实例：** 尚未配置跨实例共享状态、消息适配器及负载均衡策略，不应直接扩容为多个实例。
- **身份为原型机制：** 联机重连依赖浏览器本地保存的身份令牌；清除存储或更换浏览器后不能沿用原身份，未实现账号体系。
- **未验证规模化运行：** 尚未提供正式负载测试、服务可用性或真实用户体验结论。
- **公网部署需进一步收紧静态目录：** 当前 Express 将项目根目录作为静态目录，公开部署前应改为仅发布必要的前端文件，避免暴露服务端源码、测试及其他非公开文件。
